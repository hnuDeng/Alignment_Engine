## 二、核心发现

### 2.1 路线1的隐藏缺陷

| 缺陷 | 描述 | 证据强度 | 改进方案 |
|------|------|----------|----------|
| 局部最优陷阱 | CEM在非凸空间中容易陷入局部最优 | [猜测] | 学习提议分布 |
| 指数误差累积 | 世界模型预测误差随时间步累积 | [推断] | 集成模型 + 频繁重规划 |
| 表示瓶颈 | 单一潜在向量难以表示多模态未来 | [推断] | 多模态/扩散表示 |
| 时域两难 | 短时域近视，长时域误差累积 | [事实] | 自适应/分层规划 |

### 2.2 路线4的Action数据格式

**核心结论：** Action是低层数值，不是高层语义信息。

**数据格式：**
- 关节角度：[θ1, θ2, ..., θn] ∈ ℝ^n
- 关节速度：[ω1, ω2, ..., ωn] ∈ ℝ^n
- 关节力矩：[τ1, τ2, ..., τn] ∈ ℝ^n
- 末端执行器位姿：[x, y, z, qx, qy, qz, qw] ∈ ℝ^7

**为什么是数值：**
1. 物理引擎需要数值输入
2. 语义信息是模糊的
3. 逆动力学模型学习数值映射
4. 控制频率要求100-1000Hz

### 2.3 高层语义到物理引擎的映射

**映射管道：**
```
自然语言指令 → LLM理解 → 结构化意图 → 技能选择 → 参数生成 → 低层控制
```

**四种方案：**
1. **语言描述 + 技能库匹配**：灵活但依赖技能库
2. **结构化JSON + 直接解析**：精确但需要学习格式
3. **Python代码 + 代码执行**：可组合但有安全风险
4. **参数化动作 + 参数映射**：高效但需要预定义空间

### 2.4 LLM物理推理能力

**测试结果：**
- 定性准确率：100%（10/10场景）
- 定量准确率：30%（3/10场景）
- 置信度校准：ECE = 0.11

**结论：** LLM擅长定性预测，不擅长定量预测。

## 四、最终方案：分层LLM规划 + 双循环验证

### 4.1 方案概述

**核心思想：**
- 使用LLM分层分解任务
- 使用运动原语库执行子任务
- 使用物理验证器验证轨迹
- 如果验证失败，反馈给LLM重新规划

**系统架构：**
```
┌─────────────────────────────────────────────────────────────────┐
│            LLM Hierarchical Planning + Dual-Loop Verification      │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐       │
│  │  用户指令    │ -> │  任务分解器  │ -> │  子任务序列  │       │
│  └──────────────┘    └──────────────┘    └──────────────┘       │
│                                              ↓                   │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐       │
│  │  运动原语    │ <- │  原语选择器  │ <- │  子任务描述  │       │
│  └──────────────┘    └──────────────┘    └──────────────┘       │
│         ↓                                                        │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐       │
│  │  参数优化器  │ -> │  轨迹生成器  │ -> │  关节轨迹   │       │
│  └──────────────┘    └──────────────┘    └──────────────┘       │
│         ↓                                                        │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐       │
│  │  物理验证器  │ -> │  反馈调整器  │ -> │  重规划器   │       │
│  └──────────────┘    └──────────────┘    └──────────────┘       │
│         ↓                                                        │
│  ┌──────────────┐    ┌──────────────┐                            │
│  │  执行器      │ -> │  环境反馈   │                            │
│  └──────────────┘    └──────────────┘                            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 核心创新点

1. **分层任务分解**：使用LLM将复杂任务分解为简单子任务
2. **运动原语库**：预定义的运动原语，支持组合和扩展
3. **双循环验证**：LLM规划 + 物理验证，迭代优化
4. **反馈机制**：验证器反馈错误给LLM，指导重新规划

### 4.3 技术细节

**LLM任务分解器：**
- 输入：自然语言指令 + 场景描述
- 输出：子任务序列（JSON格式）
- 机制：使用LLM理解任务意图，分解为子任务

**原语选择器：**
- 输入：子任务描述
- 输出：运动原语 + 参数
- 机制：从预定义库中选择合适的原语

**参数优化器：**
- 输入：运动原语 + 初始参数
- 输出：优化后的参数
- 机制：使用梯度下降优化参数

**轨迹生成器：**
- 输入：运动原语 + 参数
- 输出：关节轨迹
- 机制：使用逆运动学生成轨迹

**物理验证器：**
- 输入：关节轨迹
- 输出：验证结果
- 机制：检查碰撞、关节限位、速度限制

**反馈调整器：**
- 输入：验证结果
- 输出：反馈信息
- 机制：分析失败原因，生成反馈

**重规划器：**
- 输入：反馈信息
- 输出：新的规划
- 机制：根据反馈调整规划

## 十、核心结论

### 10.1 事实性结论

1. **路线4的Action是低层数值**：关节角度、力矩等，不是语义信息
2. **物理引擎需要数值输入**：语义信息无法直接控制执行器
3. **LLM定性预测可靠**：在简单物理场景中，LLM可以正确预测方向
4. **LLM定量预测不足**：LLM无法给出精确的数值预测

### 10.2 推断性结论

1. **路线1存在时域两难**：短时域近视，长时域误差累积
2. **分层规划可以降低复杂度**：将复杂任务分解为简单子任务
3. **双循环验证可以提高成功率**：通过反馈迭代优化规划
4. **运动原语库可以提高泛化性**：预定义原语可以复用

### 10.3 猜测性结论

1. **路线1存在局部最优陷阱**：CEM在非凸空间中容易陷入局部最优
2. **路线1存在指数误差累积**：世界模型预测误差随时间步累积
3. **路线1存在表示瓶颈**：单一潜在向量难以表示多模态未来
4. **LLM可以准确分解任务**：需要实验验证

### 10.4 最终方案

**分层LLM规划 + 双循环验证**
- 使用LLM分层分解任务
- 使用运动原语库执行子任务
- 使用物理验证器验证轨迹
- 如果验证失败，反馈给LLM重新规划
