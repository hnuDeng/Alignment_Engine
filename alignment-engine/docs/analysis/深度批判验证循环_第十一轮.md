## 一、范式对比：传统方法 vs 我们的方法

### 1.1 传统方法范式

**范式1：端到端学习**
```
观测 → 神经网络 → 动作
```
- 优点：简单，端到端优化
- 缺点：不可解释，需要大量数据

**范式2：模型预测控制（MPC）**
```
观测 → 世界模型 → 规划 → 动作
```
- 优点：可解释，可利用模型
- 缺点：模型误差累积，计算量大

**范式3：强化学习**
```
观测 → 策略网络 → 动作 → 奖励 → 更新策略
```
- 优点：可以从交互中学习
- 缺点：样本效率低，奖励设计困难

### 1.2 我们的范式

**范式4：语言引导的分层规划**
```
语言指令 → LLM分解 → 子任务序列 → 原语选择 → 参数优化 → 轨迹 → 物理验证 → 执行
```

**核心差异：**
1. **语言作为接口**：使用自然语言作为人机接口
2. **分层结构**：明确的层次结构
3. **物理验证**：显式的物理验证
4. **双循环反馈**：闭环反馈机制

### 1.3 范式优势分析

| 维度 | 端到端 | MPC | 强化学习 | 我们的方法 |
|------|--------|-----|----------|------------|
| 可解释性 | 低 | 中 | 低 | 高 |
| 样本效率 | 低 | 中 | 低 | 高 |
| 泛化能力 | 中 | 低 | 中 | 高 |
| 安全性 | 低 | 中 | 低 | 高 |
| 灵活性 | 高 | 低 | 高 | 高 |
| 计算效率 | 高 | 低 | 高 | 中 |

## 二、新范式的理论创新

### 2.1 创新1：语言作为任务表示

**传统方法：**
- 任务用目标状态表示
- 任务用奖励函数表示
- 任务用约束表示

**我们的方法：**
- 任务用自然语言表示
- LLM理解语言含义
- 转换为结构化表示

**理论优势：**
1. **表达能力强**：自然语言可以表达任意任务
2. **灵活性高**：可以处理模糊指令
3. **人机友好**：自然语言是人类自然接口

**理论挑战：**
1. **歧义性**：自然语言有歧义
2. **不精确性**：自然语言不精确
3. **理解难度**：LLM可能误解

### 2.2 创新2：分层任务分解

**传统方法：**
- 扁平的任务表示
- 直接从状态到动作
- 没有中间抽象

**我们的方法：**
- 分层的任务表示
- 多层抽象
- 每层有明确语义

**理论优势：**
1. **降低复杂度**：每层处理更简单的问题
2. **提高可解释性**：每层有明确含义
3. **支持组合**：可以组合不同层

**理论挑战：**
1. **层次设计**：如何设计合适的层次
2. **层间通信**：如何在层间传递信息
3. **误差传播**：误差如何在层间传播

### 2.3 创新3：物理验证反馈

**传统方法：**
- 开环规划
- 没有验证
- 执行后才知道失败

**我们的方法：**
- 闭环规划
- 物理验证
- 执行前就知道可行性

**理论优势：**
1. **安全性高**：执行前验证安全性
2. **可靠性高**：减少执行失败
3. **可调试性**：容易定位问题

**理论挑战：**
1. **验证准确性**：验证器是否准确
2. **验证效率**：验证是否高效
3. **验证完备性**：验证是否完备

## 三、新范式的能力边界

### 3.1 能力上界分析

**理论上界：**
- LLM理解能力上界
- 运动原语覆盖上界
- 优化器能力上界
- 验证器准确性上界

**实际上界：**
- 取最弱环节
- 通常是LLM理解能力

### 3.2 能力下界分析

**理论下界：**
- 随机规划的性能
- 规则规划的性能
- 纯优化的性能

**实际下界：**
- 取决于实现质量
- 通常高于随机规划

### 3.3 能力边界条件

**成功条件：**
1. 任务在LLM理解范围内
2. 任务可以用原语表示
3. 任务有可行解
4. 验证器准确

**失败条件：**
1. 任务超出LLM理解范围
2. 任务无法用原语表示
3. 任务无可行解
4. 验证器不准确
